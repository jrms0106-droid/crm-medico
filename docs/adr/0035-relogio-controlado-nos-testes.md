# ADR 0035: relógio controlado nos testes no navegador

- **Status:** aceito (2026-11-02, escolha do responsável)
- **Contexto:** Os testes no navegador marcam consultas para hoje. Entre 23:00 e 00:00 (horário de Brasília) não sobra horário livre no dia e o teste do assistente clínico falhava sem defeito no sistema; no PR #43 o CI só passou ao repetir depois da meia-noite. A API já lê o horário por uma fonte injetável (`Clock`), mas os testes no navegador usavam o relógio real.
- **Decisão:** Nova variável `CLOCK_OFFSET_MINUTES` (inteiro, padrão 0, até 7 dias para frente ou para trás) desloca o relógio da API. `loadConfig` recusa qualquer valor diferente de 0 com `NODE_ENV=production`. Nos testes no navegador, `e2e/clock.ts` calcula uma vez o deslocamento que leva ao próximo 10:00 de Brasília (de 0 a 24 horas para frente) e o mesmo valor vai para a API, para o navegador (`page.clock.install`, pela fixture de `e2e/test.ts`) e para o gerador de códigos de MFA dos testes. O relógio continua andando a partir desse ponto.
- **Motivo:** Com API, navegador e MFA no mesmo horário, os testes ficam iguais a qualquer hora do dia e continuam passando pelo caminho real (banco, política de acesso, sessão). Deslocar só para frente evita que algo pareça ter sido criado no futuro.
- **Alternativas descartadas:** marcar sempre no dia seguinte nos testes (muda o fluxo testado e o relógio do navegador continuaria diferente do da API); congelar o relógio (`setFixedTime` quebra tempos de espera do próprio teste e do aplicativo); rota de teste para mudar o horário em tempo de execução (seria uma rota a mais para proteger); repetir o teste quando falha (esconde o problema).
- **Consequências:** As datas gravadas pelo padrão do banco (`created_at` com `now()`, por exemplo no cadastro de paciente) seguem o horário real e podem ficar até 24 horas atrás do relógio dos testes; hoje nenhuma regra compara essas datas com o relógio da API nos fluxos testados. A variável fica na configuração de produção como uma verificação a mais, não como recurso.
- **Revisar quando:** Algum teste precisar de horários específicos (por exemplo, virada de dia ou fim de mês), ou o banco passar a calcular datas usadas em regras.
